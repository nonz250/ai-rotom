# packages/site/

公式のリモート MCP サーバーと同じ URL の `/` で配る紹介サイト。Astro で静的に書き出す。

## 公式サーバーにだけ載せる

- 公式のデプロイのワークフローが `wrangler deploy --assets` で Worker と一緒に上げる。`wrangler.toml` に `[assets]` を書かない。書くと、自分でデプロイする人の Worker にも、公式の URL や招待コードを載せたサイトが出る
- 静的アセットは Worker の処理より前に返るので、`/mcp` と同じパスのファイルを置かない。置くと MCP のリクエストがファイルに吸われる
- ワークフローは Worker のバンドルとサイトを別のディレクトリに分けて照合する。`--no-bundle` の wrangler は入口と同じディレクトリの `.js` をモジュールとして上げるので、1 つのディレクトリにまとめない

## 中身の約束

- 「サーバー利用時の注意事項」と接続先の値は、README と `packages/remote-server/docs/connect-prompt.md` と同じ内容にそろえる
- 使い方の例の答えは、ai-rotom を使える AI に実際に質問して返ってきた答えを要約したもの。数値を手で作らない。データを直したら答えを出し直す
- フッターの著作権・商標と、ライセンスの表示を外さない。README と同じく、権利者に向けた表明なので残す
- ポケモンの画像やロゴを使わない。アイコンはオリジナルの図形にする

## 依存

- `cookie` を固定しているのは、ビルド時のプリレンダーが `cookie` を `packages/site` から読むため。ルートには express が使う古い版が hoist されていて、astro が求める名前付き export がない。astro を上げて不要になったら外す
